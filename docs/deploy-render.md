# Deploying the 15 services on Render (Free plan)

Everything runs from one Blueprint (`render.yaml`, generated by `scripts/build_render_yaml.py`). AWS stays as already deployed.
Do the steps in this order.

## 1. Put the code on GitHub (private repo)
```powershell
cd E:\dev\docindex
git init -b main
git add .
git status            # check: no secrets\ folder, no .env, no render-urls.json, no infrastructure\generated
git commit -m "CleanDocs AI"
gh repo create cleandocs-ai --private --source . --push     # or create an empty private repo on github.com, then:
# git remote add origin https://github.com/<you>/cleandocs-ai.git ; git push -u origin main
```

## 2. Create the AWS access keys (one per tier, least privilege)
```powershell
.\scripts\create-access-keys.ps1
```
Writes `secrets\aws-ingest.env`, `aws-processing.env`, `aws-indexing.env` (git-ignored). You delete the folder in step 3.

| Tier (IAM user) | Used by |
|---|---|
| ingest (`cleandocs-ingest`) | upload, archive |
| processing (`cleandocs-processing`) | validation, manifest, normalization, cleaning, duplicate, extraction, metadata, chunking, embedding, entity-extraction, graph |
| indexing (`cleandocs-indexing`) | vector-indexing, reconciliation |

## 3. Create four environment groups in the Render dashboard (before the Blueprint)
Render does not prompt for values inside Blueprint env groups, so the secret groups are made by hand. Dashboard -> Environment Groups -> New Environment Group. Names must match exactly.

| Group | Content |
|---|---|
| `cleandocs-auth` | `SERVICE_AUTH_SECRET` = the same value you used in `deploy-orchestration.ps1` |
| `cleandocs-aws-ingest` | "Add from .env": paste `secrets\aws-ingest.env` |
| `cleandocs-aws-processing` | paste `secrets\aws-processing.env` |
| `cleandocs-aws-indexing` | paste `secrets\aws-indexing.env` |

Then: `Remove-Item -Recurse -Force secrets`
If you lost the auth secret: choose a new one, put it in `cleandocs-auth`, and rerun `.\scripts\deploy-orchestration.ps1` with the same value.

## 4. Create the services from the Blueprint
Render dashboard -> New -> Blueprint -> pick the repo, branch `main`, file `render.yaml` -> Apply.
It creates group `cleandocs-config` (non-secret settings) and 15 free Docker web services in Frankfurt. First builds take several minutes each.
Every service shows "Live" when `/health/live` answers. `autoDeploy` is off on purpose: all services share `shared/`, so an automatic deploy would rebuild all 15 images and use up free build minutes. To update: change code, push, then Manual Deploy on the services that changed (all of them if `shared/` changed).

## 5. Check the real URLs
Render adds a suffix when a name is taken, so do not assume `https://cleandocs-<name>-service.onrender.com`.
```powershell
$env:RENDER_API_KEY = "rnd_..."        # Render: Account Settings -> API Keys
.\scripts\render-urls.ps1               # writes render-urls.json and prints every URL
```
If any URL differs from the default pattern, repoint the workflows (this also re-applies everything else, safely):
```powershell
$env:SERVICE_AUTH_SECRET = "<your secret>"
.\scripts\deploy-orchestration.ps1 -UrlsFile render-urls.json
```

## 6. End-to-end test
```powershell
$env:SERVICE_AUTH_SECRET = "<your secret>"
python scripts\smoke_test_pipeline.py --urls-file render-urls.json
```
It wakes the services, uploads a small text file, waits for the ingestion to finish and prints the reconciliation report. Expect 5 to 15 minutes the first time because each sleeping free service needs about a minute to wake. Exit code 0 means `COMPLETED` with every check passing.

## If it does not work
| Symptom | Look at |
|---|---|
| Build fails | Render service -> Logs (build). Docker builds have not been run by me; this is the first real build. |
| Upload returns `workflow_started: false` | `STEP_FUNCTIONS_INGESTION_ARN` on upload-service and the `cleandocs-ingest` user's `states:StartExecution` |
| Execution fails at the first call | Step Functions console -> execution -> failed state. 401 means the secret differs between `cleandocs-auth` and the orchestration stack. A DNS/connection error means a wrong URL (step 5). |
| Stuck in "waiting for files" | The dispatcher: Lambda logs `/aws/lambda/cleandocs-dispatcher`; the SQS queue; the DLQ |
| `PARTIAL` / `FAILED` | The reconciliation report lists the failed checks per document |

## Cost
Render Free: $0 (750 instance hours per workspace per month; services sleep when idle). AWS (approximate, home-lab volumes): Step Functions Standard is billed per state transition with a small monthly free allowance; each document uses a few dozen transitions plus readiness retries. Textract is capped at 300 pages a month. Bedrock embedding of a few documents is a fraction of a cent. S3, DynamoDB on-demand and 14-day logs are pennies. Check the AWS Billing console after the first week.
